# Telegram-бот "Словарь с оценками"

## Что делает

- Пользователи из списка `ALLOWED_USERS` пишут боту слово
- Бот спрашивает оценку 0–10 (до тысячных)
- Слово с оценкой сохраняется в общую базу
- `/list` — весь словарь, отсортированный по оценке (доступно всем)
- `/categories` — просмотр по диапазонам оценок через inline-кнопки (доступно всем)
- При добавлении нового слова — уведомление всем из `ALLOWED_USERS`

## Установка

```bash
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка

Открой `bot.py` и заполни:

1. `BOT_TOKEN` — получить у [@BotFather](https://t.me/BotFather) (команда `/newbot`)
2. `ALLOWED_USERS` — id пользователей, которым можно добавлять слова.
   Свой id можно узнать, написав боту [@userinfobot](https://t.me/userinfobot)

## Запуск

```bash
python bot.py
```

Бот работает через long polling — не нужен ни домен, ни HTTPS, ни webhook. Достаточно,
чтобы процесс был запущен (например, на VPS через `systemd` или `screen`/`tmux`,
либо в Docker-контейнере).

## Как это устроено внутри

- **aiogram 3** — асинхронный фреймворк, диалог "слово → оценка" реализован через
  FSM (`AddWord.waiting_score`): бот "помнит", что ждёт от конкретного пользователя оценку
- **SQLite** (`words.db`) — таблица `words(word, score, added_by, added_by_name, added_at)`.
  Для такого сценария (несколько добавляющих, читатели без лимита) SQLite более чем
  достаточно; переезд на PostgreSQL понадобится только при очень большом трафике
- Рассылка уведомлений — простой цикл по `ALLOWED_USERS` с `bot.send_message`,
  ошибки (например, если пользователь заблокировал бота) не прерывают рассылку

## Куда развивать дальше

- **Список разрешённых пользователей в БД, а не в коде** — тогда админ сможет
  добавлять/убирать людей командой `/allow <id>`, не редактируя код
- **Пагинация `/list`** — сейчас список обрезается на ~3800 символах; для больших
  словарей стоит сделать постраничный вывод с кнопками "вперёд/назад"
- **Проверка дублей** — сейчас одно и то же слово можно добавить дважды с разными
  оценками; если нужно — проверять перед вставкой и предлагать обновить оценку
- **Редактирование/удаление слова** — команда `/edit`, доступная тому, кто добавил,
  или админам
- **Webhook вместо polling** — если бот будет жить на сервере с HTTPS постоянно,
  webhook немного эффективнее, но для такого объёма трафика разница не критична
